# ai-core NUI

Two screens in one page: the character screen (`src/features/characters`, its own small store and `lib/nui.ts`) and the admin panel (`src/features/admin`, the `aicore-ui` stack: Redux `src/store`, TanStack Router `src/router.tsx` for script / tab / record, Radix primitives `src/components/ui`, fivem-nui-react).

## Look

- TGIANN (`docs/design.md`): tokens in `src/index.css` (`tgi-green-*`, `panel`, `surface`, `control`, `text-2/3/4`, `danger*`), Unbounded 800 as `font-display` for uppercase titles; no other palette, no raw hex that has a token.
- Full-screen building blocks (screen title, vignette, round action, pill bar and pill buttons, column enter motion) are in `components/Screen.tsx`; shadcn primitives in `components/ui` carry the TGIANN skin (pill inputs and buttons, `primary` = the one filled green action).
- The admin panel copies tgiann-core's admin lib panel (sidebar, header, record list, section cards with an inset row list).
- Previews: `?view=create|delete|error|menu|notify|prompt|admin`; menu, notify, prompt and admin open without the character screen.

## Admin panel

- Routes: `/admin` dashboard (`Dashboard.tsx`), `/admin/setup` the setup guide (`Setup.tsx`), `/admin/$resource/$tab` a script's tab, `/admin/external/$id` another script's page in an iframe, `/admin/players` the Players section. Lookup lists, other panels and the free camera state (`picking`: the panel hides behind a key help bar) live in the admin slice.
- Sidebar (`Sidebar.tsx`, row pieces in `SidebarItems.tsx`): the dashboard, then every script (only the open one shows its tabs), then the "Other panels" category (`OtherPanelsNav.tsx`): one entry per external panel (`openExternal`: a page in the iframe or its command) plus ai-core's `external` tab, the editor that adds them, which is therefore left out of the Server group. Labels wrap to two lines, then end with an ellipsis (`NavLabel`, full text in `title`).
- Players section (`features/admin/players/`, route `/admin/players`, one character `?char=<id>`, sidebar row under the dashboard): its own Redux slice (`players`: online rows, the open `CharacterView`, its status) fed by the `online` / `open` snapshots and `adminPlayers` deltas; every call goes through `players/actions.ts` (one NUI callback `adminPlayers { action, args }`). The online list filters as you type; at 2+ characters the stored search runs (Pacer debounce 300 ms, Load more = the next keyset page; results are a query answer, not live). The character page is cards: character form (name, birth date, nationality, sex; saved together), money (account, add / remove / set, reason), jobs and gangs (grade select, duty / active switch, remove, add via `LookupBox`; job and grade labels from ai-core's panel data), position (Go to, Bring), items (online), player actions (revive; kill, kick and delete behind a dialog), metadata (scalars edited in place, objects as JSON). Preview mock `dev/playersMock.ts`: `?view=admin#/admin/players`, `?char=3` online, `?char=2` offline, `&error=1` refuses edits.
- Global search (`GlobalSearch.tsx` in the header, Ctrl+K, and the dashboard box) runs on one index (`searchIndex.ts`: scripts, tabs, every field label / hint / card, records by their label) built from the open snapshots in the admin's language; a hit opens the tab (the record), a settings field scrolls into view and flashes (`jumpTo`, admin slice `focus`, `FieldShell`).
- Setup guide: steps in `setupSteps.ts` name fields of any script's panel (`resource`, `file`, `key?`, `path`); each renders the field's own widget from that script's schema, so it saves live like its tab; steps whose scripts do not run are left out. The panel opens on it while ai-core's `setupDone` is off; the last step sets it. The welcome card players see after spawning meanwhile is `features/setup/Welcome.tsx` (`?view=welcome`, `&admin=1`).
- Lookup fields: `widgets/lookup.tsx` (`LookupBox` on the Radix popover, arrows / Enter / Escape, 40 shown); `TextW` and `TagsW` switch to it when the spec has `lookup`; a stored value the game does not know shows a red "Not found" chip. Name suggestions (`suggest`, `widgets/suggest.tsx`): a wand button inside the text box's right end opens the names in a popover under the box (no extra height, so it fits list rows). Suggestions and the free camera point pick ask ai-core's client (`adminPlaceNames`, `adminPickPoint`). Teleport buttons send `ground` (point `spec.ground`, always for `entity`): the client stands the ped on the point with `SetEntityCoords`, else `SetEntityCoordsNoOffset`.
- Action widget (`widgets/ActionW.tsx`): a button that sends `{ action: "run", id: <path> }` through the same apply callback (`runAction`); `confirm` opens the TGIANN dialog first; the script's answer shows under it like a field's save state. Zone widget (`widgets/ZoneW.tsx`): corners from `pickPoint` / `myPosition`, listed with teleport and remove; while mounted it sends the corners and height to `adminZoneDraw` (client `resource/client/zoneDraw.ts` draws the edges per frame) and `null` on unmount.
- Blip widget: `widgets/BlipW.tsx` with `blips.json` (FiveM blip reference: sprite names, pictures at docs-backend.fivem.net, colours).
- Schema driven: `Field.tsx` only dispatches, each widget is in `widgets/`; a new widget = a new case there plus the spec in `@aicore-fivem/shared` `admin.ts`. Any widget may carry `showIf: { path, values }` (path read like the field's own, from the record or settings object): `Field` renders nothing while that value is not one of `values` (a missing value never matches; list rows ignore it).
- A records tab with `table` renders `TableView` (read-only, search over every column, `VirtualList` rows, header and rows share `scrollbar-gutter: stable` so columns line up); `info` and table cells share `showValue` (`values` / `empty` labels).
- Every navigation and NUI call goes through `features/admin/actions.ts` (the Players section: `players/actions.ts`); components never call the router or fetchNui.
- Live save per field: the value shows at once, `FieldShell` shows saving / saved / the refusal under the field; a list shows the state of its rows.
- Texts: the script's own lang table first, ai-core's generic panel words second (`lang.ts`).
- Browser preview: `bun run webdev`, `?view=admin#/admin/ai-core/<tab>?key=<record>` (real schema and data files from `dev/adminMock.ts`, sample keybinds and commands there since those come from running scripts), `&error=1` refuses every edit.
- Another script's panel in the browser: fivem-nui-react listens to messages only when `window.invokeNative` exists, so define it before the page loads (puppeteer `evaluateOnNewDocument`), open `#/admin/<resource>/<tab>?key=<record>` and post `{ action: "adminOpen", data: { panels: [{ resource, schema, texts, data }], texts } }` built from the script's schema, `data/*.json` and `locales/en.json`.

## Pitfalls

- `components/ui/popover.tsx` ignores interactions inside its anchor (`onInteractOutside`): without it a popover opened from the input's focus (every `LookupBox`) closes at once on the first click, because Radix's focus-outside listener sees that same `focusin` (`aicore-ui` `foundation.md`). Keep it when touching the primitive.
- Radix ScrollArea wraps its content in a `display: table` box that grows with long text, so `truncate` never triggers inside it; `components/ui/scroll-area.tsx` forces that box to `block`. Keep it when touching the primitive.
- In the in-game preview mode (`window.invokeNative` defined) `fetchNui` posts to `https://<resource>/...` for real and gets CORS errors; a puppeteer test answers them with request interception (OPTIONS 204 + `Access-Control-Allow-Origin: *`, a JSON body per callback name).
- `useNuiEvent`'s `mockData` must be one stable reference (module constant): a new object per render re-runs the effect and the browser mock re-opens the panel with the original data after every edit.
