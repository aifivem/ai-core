# Hunger and thirst (server)

ai-core keeps every character's hunger and thirst (owner decision: one place, every value in ai-core's panel; a HUD only draws). Client half: `resource/client/needs.ts`. Compatibility: `docs/compat/stress.md`.

- Storage: character metadata `hunger` / `thirst` (QB's keys, 0-100, 100 = full), whole numbers. `store.ts` is the only writer: it keeps the decimals per loaded `Player` (a `WeakMap`, gone with the object) and calls `Player.setMeta` only when the whole number changes, so the owner gets one metadata patch (player data channel), the bridges one `metaChanged` (QB `PlayerData`, Qbox state bags) and the periodic save writes it with the rest of the metadata; never a DB write of its own. A value someone else put into metadata (a QB script's `SetMetaData`, the admin panel's character card) wins over the kept decimals at the next change.
- Stress is written by the same store while ai-hud is the stress HUD (`stress/registry.ts`'s ai-hud adapter): a second store in ai-hud would be a second copy of this writer. ai-hud keeps the stress rules (client sources, panel values) and answers `GetStressRelief()`; with a QB-style HUD that HUD keeps stress itself.
- Start values: `store.seed` fills missing keys of the row's metadata with the panel's `start` values before `Player.load` (a new character, or one from before), so the load snapshot and the bridges see them; no event.
- Decay (`decay.ts`): one `every(1000)` job; each second it walks the loaded players once and handles the slice whose server id % 60 is that second, so each player's minute passes once a minute and a full server's metadata writes spread over 60 frames (O(loaded players) per second, no per-player timers, no export call per player). Hunger and thirst drop by the panel's rates while `decay.enabled`; stress fades by the active HUD's `relief()` (asked once per pass, only when the slice has someone). It keeps running while the player is down (QB's behaviour; a revive with lib `needs.refill` fills them).
- Item effects: `CORE.itemUsedEvent` status `hunger` / `thirst` add to the store, `stress` goes to the stress layer (`addStress`: the HUD that keeps it).
- Display: after a whole-number change of hunger or thirst the stress layer's active HUD draws it (`showNeeds`): QB-style HUDs get QB's `hud:client:UpdateNeeds (hunger, thirst)`, ai-hud reads ai-core's player data, and without a known HUD QB's event goes out anyway (any QB HUD listens to it).
- Exports `RefillNeeds`, `AddNeed` (-100..100, not 0), `SetNeed` (clamped) answer false for a player without a character; lib `needs.refill` / `add` / `set`, Lua `aiLib.needs`; the Qbox `consumables:server:*` events, qbx_smallresources' exports and vRP's survival functions call them.
- Panel: `schema.ts` (`data/needs.json`, tab Hunger and thirst), defaults and reader in `resource/common/needs.ts` (the client reads the same file through `AdminWorld`). The warnings (notify, dizziness, health loss) run on the client: it owns its ped's health.
